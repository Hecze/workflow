`produce` is experimental. See [`workflow/state`](/docs/api-reference/workflow-state).
</Callout>

Creates the next version of `base` by running `recipe` against a mutable draft. It behaves like [immer's `produce`](https://immerjs.github.io/immer/produce): the result is frozen, shares every unchanged part with `base`, and `base` itself is not modified.

```typescript lineNumbers
import { produce } from "workflow/state"; // [!code highlight]

const todos = [{ title: "Write docs", done: false }];

const next = produce(todos, (draft) => { // [!code highlight]
  draft[0].done = true; // [!code highlight]
  draft.push({ title: "Ship", done: false }); // [!code highlight]
}); // [!code highlight]

todos[0].done; // false
next[0].done; // true
```

## API signature

{/* @skip-typecheck: signature only */}
```typescript
function produce<T>(
  base: T | Immutable<T>,
  recipe: (draft: Draft<T>) => void | T | Immutable<T>
): Immutable<T>;
```

### Parameters

| Parameter | Type | Description |
|-----------|------|-------------|
| `base` | `T \| Immutable<T>` | The current value: a plain value, or a value returned by an earlier `produce()` call. |
| `recipe` | `(draft: Draft<T>) => void \| T` | Edits `draft` in place. Returning a value replaces the whole result with it. |

### Returns

A frozen `Immutable<T>`. When the recipe changes nothing, `base` is returned unchanged.

### Types

| Type | Description |
|------|-------------|
| `Immutable<T>` | A deeply read-only view of `T`. |
| `Draft<T>` | A deeply mutable view of `T`, used inside the recipe. |

Both have the same shape as immer's types of the same name.

## Storage

When [state references are enabled](/docs/api-reference/workflow-state#enabling-state-references), a later step that receives a `produce()` result stores a reference instead of a copy, and the step that returned it stores only its change from `base`. Workflow computes the change by comparing the result with `base`, so it doesn't depend on how the recipe made the result:

- Editing the draft and returning a rebuilt replacement both store only what differs. Comparisons are by value, so a recipe can return copies of unchanged data.
- Growth at the end of an array is stored as an append. Other array edits are stored per element when the length is unchanged, and as the new array otherwise. Arrays with holes are stored whole.
- The result is stored whole when its base isn't in the run's log, and again once the changes stored since its last whole copy outgrow the value itself.

```typescript lineNumbers
import { produce } from "workflow/state";

const base = { history: ["Hello", "Hi!"], status: "idle" };

// A recipe returning a rebuilt value still stores only the change:
// an append of "Next?" to `history`, and a set of `status`.
const next = produce(base, () => ({
  history: [...base.history, "Next?"],
  status: "waiting",
}));
```
